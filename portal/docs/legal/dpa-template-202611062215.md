本数据处理协议("DPA")是 [WOODGIT 运营主体名称]("处理者")与 [客户名称]("控制者")之间 [主服务协议名称] 的组成部分。两者冲突时,就个人数据处理事项以本 DPA 为准。

## 1. 定义
"个人数据""处理""控制者""处理者""数据主体""子处理者"等,采用 GDPR 第 4 条的定义。"客户内容"指控制者或其授权用户通过服务提交并由平台转发至 AI 模型供应商的 prompt 与接收的 response。

## 2. 角色
- 就**客户内容**及控制者在服务中的最终用户个人数据,处理者作为**处理者**,仅按控制者的记录指令处理(本 DPA 与客户对服务的使用即构成指令)。
- 就**账号与计费数据**(注册邮箱、姓名、企业信息、发票抬头、支付记录),处理者作为**独立控制者**,用于提供与计费服务。

## 3. 处理说明(附件 A)
见文末附件 A。

## 4. 处理者义务
处理者应:
(a) 仅按控制者书面指令处理个人数据,法律另有要求的除外;
(b) 确保被授权处理人员负有保密义务;
(c) 采取附件 B 所述的技术与组织措施(GDPR 第 32 条);
(d) 遵守第 5 条的子处理者条款;
(e) 在技术可行范围内协助控制者响应数据主体权利请求(平台提供导出 `/gdpr/export`、删除申请与匿名化能力);
(f) 协助控制者履行第 32–36 条义务(安全、泄露通知、DPIA);
(g) 服务终止后,依控制者选择删除或返还个人数据,法律要求保留的除外;
(h) 向控制者提供证明合规所需的信息,并允许 [每年一次 / 发生泄露后] 的审计或问卷。

## 5. 子处理者
- 控制者**一般性授权**处理者使用附件 C 所列子处理者。
- 新增或更换子处理者时,处理者应**提前 [30] 天**通过 [邮件 / 子处理者页面订阅] 通知;控制者可在 [ ] 天内基于合理数据保护理由反对。
- 处理者应与各子处理者签订不低于本 DPA 的数据保护义务。
- **中转/聚合类供应商**(见附件 C B 组)会将数据再转发至下游。除非控制者另行书面同意,平台 [默认不启用 / 仅启用以下] 此类通道:[ ]。

## 6. 数据主体权利
处理者提供自助导出、删除申请、以及删除后经 [90] 天保留期的匿名化。收到直接面向处理者的数据主体请求时,处理者应在不无故拖延的情况下转交控制者。

## 7. 个人数据泄露
处理者在知悉泄露后应**不无故拖延且不迟于 [72] 小时**通知控制者,提供第 33(3) 条所需信息。平台的防篡改审计日志(哈希链 + 每日 HMAC 锚点)用于支持取证。

## 8. 跨境传输
个人数据可能被传输至附件 C 所列子处理者所在的 [美国 / 中国 / 欧盟等] 地区。此类传输依据 [标准合同条款 SCC / 其他适当保障] 进行。应控制者要求,平台 [可 / 暂不] 将路由限定于特定地区的供应商(见合规评估路线图)。

## 9. 期限与终止
本 DPA 在主协议存续期间有效;终止后处理者依第 4(g) 条处理数据。

## 10. 留存
客户内容的留存期限由控制者在服务中配置(按企业 [1–365] 天;平台默认 [90] 天)。到期后按配置的模式(off / 仅元数据 / 标准)清理。

## 附件 A — 处理说明
- **处理主体事项**:为提供 AI API 聚合与分发服务而转发客户内容并记录用量。
- **处理时长**:主协议存续期间 + 配置的留存期。
- **处理性质与目的**:接收请求 → 鉴权与额度校验 → 转发至所选模型供应商 → 返回响应 → 记录计费与审计。
- **个人数据类型**:prompt/response 中可能包含的任何内容(由控制者的使用决定);最终用户的 API Key 标识、IP、User-Agent;账号层面的邮箱/姓名。
- **数据主体类别**:控制者的员工与授权最终用户。
- **特殊类别数据**:平台不要求也不预期;若控制者提交,由控制者负责合法性基础。

## 附件 B — 技术与组织措施(现状,随路线图更新)
- **访问控制**:RBAC(四级角色)、bcrypt 口令、登录限速与锁定、每企业 OIDC SSO(可选)、TOTP MFA(可对管理员/企业强制)。
- **传输加密**:对外 HTTPS + HSTS。VPC 内部组件间链路加固 [进行中]。
- **静态加密**:上游密钥 AES 加密存储;数据库卷与备份加密 [进行中]。
- **租户隔离**:留存数据按企业目录隔离并做路径校验;数据库共享表 + 应用层隔离。
- **审计与完整性**:审计日志为防篡改哈希链,带每日签名锚点与校验接口;每个请求的 trace_id 贯通审计/用量/留存。
- **留存与销毁**:按企业可配置,清理以当前策略为准;删除申请经保留期后匿名化。
- **监控**:健康、磁盘、备份新鲜度、用量对账的持续检查与告警。
- **变更管理**:版本控制 + CI 门禁(构建/静态检查/漏洞扫描/测试);分支保护与同行评审 [进行中]。
- **业务连续性**:每日数据库备份;异地加密备份与定期恢复演练 [进行中]。
