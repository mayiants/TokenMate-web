# CI/CD 需求与实施方案

> 生成时间：2026-06-18 08:41  
> 范围：`ai-portal-go`（Portal）与 `ai-proxy-go`（Proxy）  
> 背景：项目接近尾声，需要建立完整、可维护的 CI/CD 流程，既能守住回归，又不会因重型 E2E 导致每次提交都长时间阻塞。

---

## 一、讨论结论

### 1. 哪些检查应该加入 CI/CD？

经过对两个仓库的代码、脚本、测试和现有文档的梳理，建议把检查分成 **三层**：

| 层级 | 触发时机 | 目标 | 说明 |
|------|----------|------|------|
| **门禁层（Fast Gate）** | 每次 push / PR | 快速发现编译、格式、单元测试、静态审计问题 | 必须保持 < 3 分钟 |
| **回归层（Regression）** | 每次 PR / 合并前 | 启动真实服务后做页面/接口级回归 | 5–10 分钟可接受 |
| **全量层（Full Suite）** | 每晚 / Release 前 / 手动 | 完整 Playwright E2E、性能/压力、跨服务集成 | 30 分钟以上 |

具体检查项见下文「三、建议加入 CI/CD 的检查项」。

### 2. 页面调整后，i18n 与 console 脚本是否需要同步升级？现在加入 UI 检查是否合适？

**结论：现在可以加入，但需要明确维护责任。**

- **i18n 审计（`i18n_full_audit.py`）**：不依赖浏览器，扫描模板/JS/Go 中的 key 使用和中文字符。新增页面或字段时，只要遵循 `_t('...')` / `{{t "..."}}` 规范，一般不会破坏；若引入新的硬编码中文或新 key，审计会立即标红。这是**最适合进 CI 的 UI 检查**。
- **Console 错误扫描（`e2e/scan-console-errors.js`）**：本质仍是 Node + Playwright 浏览器脚本，需要 Portal 已启动并 seeded。它内部维护了一份 `PAGES` 路由表。如果新增/删除/重命名页面，需要同步更新该脚本。建议作为**回归层**检查，而不是每次 push 的门禁。
- **Playwright 完整 E2E（`e2e/*.spec.js`）**：耗时长、依赖多、需要真实测试账号和 seed 数据。项目收尾阶段页面结构趋于稳定，此时把**轻量版本**（如 `ui-smoke.spec.js` + `ui-all-pages.spec.js`）纳入 nightly/Release 回归是合理的；但**不建议**放进每次 PR。

**当前时间点判断**：项目接近尾声，核心页面和功能已基本定型，正是加入 i18n 审计和 console 扫描的好时机。但需要在团队约定：

> 新增页面时，同步更新 `e2e/scan-console-errors.js` 的 `PAGES` 表；新增静态文案时，同步补充 `en.json` / `zh.json`。

### 3. 总体实施原则

1. **先跑通、再加重**：先用 Fast Gate 保证基础质量，再逐步加入 regression/nightly。
2. **优先无服务依赖的检查**：编译、`go vet`、格式化、Python 审计脚本可以先上。
3. **服务依赖用 Docker Compose 提供**：CI 里启动 `docker-compose.portal.yml`（Portal + Postgres + Redis）后再跑需要运行服务的检查。
4. **不把重型 Playwright 塞进每次 push**：避免 PR 等待时间过长。
5. **先修已知阻塞项**：Proxy 的 `TestPricingCache` 失败、`go vet` 自赋值警告等。

## 三、建议加入 CI/CD 的检查项

### 3.1 Fast Gate（每次 push / PR）

#### Portal

| 检查 | 命令 | 耗时 | 备注 |
|------|------|------|------|
| Go 编译 | `go build -o portal ./cmd/server` | ~30–60s | 无外部依赖 |
| `go vet` | `go vet ./...` | ~10s | 当前通过 |
| `gofmt` 检查 | `gofmt -l .` | ~5s | 不应有输出 |
| 无 DB 单元测试 | `go test ./internal/middleware/... ./internal/web/... ./pkg/... ./tests/performance/... -v` | ~30s | 不依赖 Postgres；`internal/services/...` 需要 Postgres，暂不在 Fast Gate |
| i18n 完整审计 | `python3 scripts/i18n_full_audit.py --strict` | ~10–30s | **重点推荐**，目前 0 issue |
| Tailwind 重建校验 | `bash scripts/rebuild-tailwind.sh` | ~10s | 防止 CSS 过时 |

#### Proxy

| 检查 | 命令 | 耗时 | 备注 |
|------|------|------|------|
| Go 编译 | `go build -o ai-proxy-go ./cmd/server` | ~30–60s | 无外部依赖 |
| `go vet` | `go vet ./...` | ~10s | **先修 2 处自赋值警告** |
| `gofmt` 检查 | `gofmt -l .` | ~5s | 不应有输出 |
| `golangci-lint` | `golangci-lint run ./...` | ~30s | 已注释；需先新增 `.golangci.yml` 并修复现有问题后再启用 |
| 单元测试 | `go test -v -race ./...` | ~1–2min | `TestPricingCache` 已修复 |
| Docker 构建 | `docker build -t ai-proxy-go:ci .` | ~1–2min | 验证镜像可构建 |

### 3.2 Regression（每次 PR / 合并前，或每晚）

需要启动服务（CI 内用 Docker Compose）。

#### Portal + Proxy 联合

| 检查 | 命令 | 耗时 | 备注 |
|------|------|------|------|
| 启动 Portal 堆栈 | `docker compose -f docker-compose.portal.yml up -d` | ~1–2min | Postgres + Redis + Portal |
| 启动 Proxy | `docker build ... && docker run ...` 或本地 `./start.sh` | ~1min | 需要 Portal 已健康 |
| DB 单元测试 | `go test ./internal/db/... ./internal/routes/... -v` | ~1min | 需要 Postgres |
| Console 错误扫描 | `node e2e/scan-console-errors.js --gate` | ~1–2min | 需要 Portal + 测试账号 |
| 接口冒烟测试 | `bash tests/test-portal-quick.sh` | ~30s | 需要 Portal |
| 字段对齐检查 | `python3 scripts/scan-field-alignment.py` | ~10s | 可选 |
| Schema 一致性 | `python3 scripts/check_schema_vs_code.py` | ~10s | 可选 |

### 3.3 Full Suite（每晚 / Release 前 / 手动）

| 检查 | 命令 | 耗时 | 备注 |
|------|------|------|------|
| Playwright 冒烟 + 全页面 | `npx playwright test e2e/ui-smoke.spec.js e2e/ui-all-pages.spec.js --workers=1` | ~5–8min | 需要完整 seeded Portal |
| i18n DOM 泄漏 | `npx playwright test e2e/i18n-completeness.spec.js --workers=1` | ~5–10min | 需要测试账号 |
| Admin 字段往返 | `npx playwright test e2e/ui-admin-field-roundtrip.spec.js --workers=1` | ~20–30min | 最重的回归 |
| Proxy 集成测试 | `bash tests/test-integration.sh` 等 | ~5–10min | 需要 Proxy + Portal |
| 性能基准 | `go test ./tests/performance/... -bench=. -benchmem` | ~2–5min | 可选 |

## 四、GitHub Actions 实施方案

### 4.1 推荐 Workflow 结构

建议创建两个 workflow：

1. **`ci-portal.yml`**：Portal 的 Fast Gate + Regression。
2. **`ci-proxy.yml`**：Proxy 的 Fast Gate + Docker 构建。
3. **`nightly-e2e.yml`**：完整 Playwright E2E + 集成测试（可失败报警但不阻塞日常）。

### 4.2 `ci-portal.yml` 示例骨架

```yaml
name: Portal CI

on:
  push:
    branches: [main, master, enterprise-cardification]
  pull_request:
    branches: [main, master, enterprise-cardification]

jobs:
  fast-gate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.24'
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: go build -o portal ./cmd/server
      - run: go vet ./...
      - run: test -z "$(gofmt -l .)"
      - run: go test ./internal/middleware/... ./internal/web/... ./internal/services/... ./pkg/... ./tests/performance/... -v
      - run: python3 scripts/i18n_full_audit.py --strict
      - run: bash scripts/rebuild-tailwind.sh

  regression:
    runs-on: ubuntu-latest
    needs: fast-gate
    services:
      postgres:
        image: postgres:15-alpine
        env:
          POSTGRES_DB: ai_proxy_portal
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: ${{ secrets.DB_PASSWORD }}
        ports: ['5432:5432']
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
      redis:
        image: redis:7-alpine
        ports: ['6379:6379']
        options: >-
          --health-cmd "redis-cli ping"
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.24'
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npx playwright install chromium
      - run: go test ./internal/db/... ./internal/routes/... -v
        env:
          DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
          # 需要让测试代码从环境变量读取 DSN，而不是硬编码密码
      - run: ./start.sh portal
        env:
          DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
          JWT_SECRET: ${{ secrets.JWT_SECRET }}
          # ... 其他必要 secrets
      - run: node e2e/scan-console-errors.js --gate
        env:
          PORTAL_URL: http://127.0.0.1:3001
```

> **注意**：上面的 `regression` job 需要先把 Portal 测试里硬编码的 DB 密码改为从环境变量读取，否则服务容器密码与测试代码不匹配。

### 4.3 `ci-proxy.yml` 示例骨架

```yaml
name: Proxy CI

on:
  push:
    branches: [main, master]
  pull_request:
    branches: [main, master]

jobs:
  fast-gate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.24'
      - run: go build -o ai-proxy-go ./cmd/server
      - run: go vet ./...
      - run: test -z "$(gofmt -l .)"
      - run: go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest
      - run: golangci-lint run ./...
      - run: go test -v -race ./...
      - run: docker build -t ai-proxy-go:ci .
```

> **注意**：`go test` 需要先修复 `pkg/billing.TestPricingCache`；`go vet` 需要先修复 2 处自赋值警告。

### 4.4 `nightly-e2e.yml` 示例骨架

```yaml
name: Nightly Full E2E

on:
  schedule:
    - cron: '0 2 * * *'
  workflow_dispatch:

jobs:
  full-e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npx playwright install
      - run: ./start.sh mvp
        env:
          # 注入生产/测试级 secrets
          DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
          JWT_SECRET: ${{ secrets.JWT_SECRET }}
          ENCRYPTION_KEY: ${{ secrets.ENCRYPTION_KEY }}
          PROXY_SYNC_SECRET: ${{ secrets.PROXY_SYNC_SECRET }}
          ADMIN_SECRET: ${{ secrets.ADMIN_SECRET }}
          APP_BASE_URL: ${{ secrets.APP_BASE_URL }}
      - run: npx playwright test e2e/ui-smoke.spec.js e2e/ui-all-pages.spec.js e2e/i18n-completeness.spec.js --workers=1
      - run: bash tests/test-integration-all.sh
```

## 五、页面变更与脚本维护

### 5.1 i18n 审计脚本的维护

`scripts/i18n_full_audit.py` 会扫描：

- JS 文件中的硬编码中文（不在 `_t()` 内）。
- HTML 模板中的硬编码中文。
- Go 后端中的硬编码中文。
- `en.json` / `zh.json` 与代码使用之间的 key 完整性、parity、orphan、空值、重复值。

**页面新增/修改时的约定**：

1. 模板里所有用户可见字符串必须包在 `{{t "key"}}` 中。
2. JS 里所有用户可见字符串必须包在 `_t('key')` 中。
3. 新增 key 必须同时写入 `en.json` 和 `zh.json`。
4. 专有名词允许加入 `web/static/js/proper-nouns.json`。
5. 用户生成内容（seed plan/voucher/model 名称、测试用户名）如果出现在 UI 扫描中，需要加入 `e2e/i18n-completeness.spec.js` 的 allowlist。

### 5.2 Console 错误扫描脚本的维护

`e2e/scan-console-errors.js` 内部维护 `PAGES` 对象：

```js
const PAGES = {
  'SuperAdmin': ['/admin', '/admin/users', ...],
  'User': ['/dashboard', '/profile', ...],
  'Enterprise': ['/enterprise', ...],
};
```

**页面新增/修改时的约定**：

1. 新增页面：把路由加到对应角色的 `PAGES` 数组。
2. 删除/重命名页面：从数组移除或修改。
3. 路由权限变更：脚本会自动检测被重定向到 `/login` 或 `/dashboard` 的情况并跳过。
4. 若出现新的已知误报（如第三方 CDN 报错），在 `createErrorCollector` 里增加过滤规则。

### 5.3 Playwright E2E 的维护

Playwright spec 依赖页面结构（selector、表单字段、按钮文字）。如果页面 HTML 结构或文案 key 变化，可能需要同步更新：

- `e2e/ui-smoke.spec.js`
- `e2e/ui-all-pages.spec.js`
- `e2e/ui-admin-field-roundtrip.spec.js`
- `e2e/i18n-completeness.spec.js`

**建议**：把 `ui-smoke.spec.js` 和 `i18n-completeness.spec.js` 作为最优先维护的 E2E；`ui-admin-field-roundtrip.spec.js` 只在 nightly 跑，可减少维护压力。

## 八、风险与建议

| 风险 | 影响 | 建议 |
|------|------|------|
| Proxy `TestPricingCache` 失败阻塞 CI | `ci-proxy.yml` 无法合并 | 先修复该测试，或在 CI 中暂时跳过并记录 TODO |
| Portal DB 测试硬编码密码 | CI 服务容器密码不匹配 | 修改测试代码从 `DB_PASSWORD` 环境变量读取 |
| Playwright E2E 不稳定 | 阻塞日常提交 | 只放 nightly，PR 不跑 |
| 页面变更后 console/i18n 脚本未同步 | CI 误报或漏报 | 在 PR template / 代码规范里明确维护责任 |
| 测试账号密码泄露 | 安全风险 | 用 GitHub Secrets 注入，删除代码中默认值 |
| CI 运行时间过长 | 开发者体验差 | Fast Gate 目标 < 3 分钟；Regression 目标 < 10 分钟 |

```bash
# Fast Gate
go build -o portal ./cmd/server
go vet ./...
gofmt -l .
go test ./internal/middleware/... ./internal/web/... ./pkg/... ./tests/performance/... -v
python3 scripts/i18n_full_audit.py --strict
```
