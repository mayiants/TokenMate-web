## 2. System Architecture

```
                    ┌──────────────────────────┐
  Users ──────────▶ │   ai-proxy-go :8080      │ ──────────▶  Upstream AI Providers
                    │   (may run on separate   │              (OpenAI, Anthropic,
                    │    hosts from Portal)    │               Bedrock, etc.)
                    │                          │
                    │  POST /api/webhook/      │
                    │   usage / usage-stats    │
                    │   retention-batch        │
                    └───────────┬──────────────┘
                                │
          Shared Redis Pub/Sub  │  Direct HTTP (if network-reachable)
         (balance, key sync)    │
                                ▼
                    ┌──────────────────────────┐
                    │  ai-portal-go :3001      │
                    │  (may run on separate    │
                    │   hosts from Proxy)      │
                    │                          │
                    │  ┌────────────────────┐  │    S3 Object Storage
                    │  │ PostgreSQL         │  │    (payloads,
                    │  │ (users, keys,      │  │     enterprise docs —
                    │  │  billing, audit,   │──┼──▶  partitioned by prefix
                    │  │  models, providers,│  │     with lifecycle rules)
                    │  │  retention_records)│  │
                    │  └────────────────────┘  │
                    │                          │
                    │  Redis (local instance)  │
                    │  webhook queues, locks   │
                    └──────────────────────────┘
```

**Key constraints:**
- Portal owns PostgreSQL (single writer)
- Proxy owns S3 credentials + object admin API (`/admin/retention/objects/*`)
- Cross-host communication: Portal webhooks accept Proxy calls; Proxy admin API is consumed by Portal server-side
- Enterprise document uploads go through Portal (not Proxy)

## 4. Active Design Proposals — Decision Gates

Two designs share S3 infrastructure and must be reviewed before implementation begins.

### Enterprise Document Storage (`docs/enterprise-document-storage-design-202606281159.md`)

| Aspect | Detail |
|--------|--------|
| **Scope** | Enterprise certification docs (business licenses, contracts, ID cards) |
| **Storage** | S3 prefix `enterprise-documents/` — explicit version folders (v1/v2/v3), not S3 versioning |
| **Metadata** | Portal `enterprise_documents` table |
| **Retention** | 7 years (GDPR legal requirement) |
| **Upload path** | Portal-mediated (recommended) or Proxy-mediated (fallback) |
| **Download** | Presigned URLs (recommended) or Proxy-proxied |
| **Est. effort** | 3-4 weeks, 4 phases (Phase 0: schema+IAM, Phase 1: upload, Phase 2: download+UI, Phase 3: retention, Phase 4: GDPR) |
| **Status** | Design submitted for review [ ] |

### Data Retention (`ai-proxy-go/docs/data-retention-design-202606281159.md`)

| Aspect | Detail |
|--------|--------|
| **Scope** | Upstream AI request/response payloads for trust-and-safety audits |
| **Storage** | S3 prefix `proxy-retention/retention-{30,90,365}/` — partitioned by day, one object per trace_id |
| **Metadata** | Portal `retention_records` (partitioned by `created_at`) |
| **Retention** | Default 30 days, admin-configurable 90 days, legal hold up to 365 days |
| **Deletion governance** | Cooling-off period (7d), legal hold override, admin review queue, deletion receipts |
| **Est. cost** | ~$365/mo @ 1k RPS (90-day retention) |
| **Est. effort** | 6-9 weeks, 5 phases (Phase 0: policy, Phase 1: Proxy foundation, Phase 2: handler integration, Phase 3: Portal ingestion, Phase 4: admin+GDRP UI, Phase 5: compliance hardening) |
| **Status** | Design submitted for review [ ] |

**Recommendation:**
- **Enterprise documents** — approve Phase 0 (schema + IAM) now; low risk, small scope. Use local storage MVP, switch to S3 later.
- **Data retention** — approve design within 1-2 weeks, then prioritize Phase 0+1 (foundation + handler integration). GDPR UI / legal hold can wait until post-launch.

## 5. Risk Register

|------|-----------|--------|------------|
| PostgreSQL connection exhaustion (inline SQL in routes with no pooling) | Medium | High | Migrate remaining routes to `internal/query/`; add connection pool metrics |

| Proxy fallback logs leak plaintext payloads | Low | Medium | P1-4 — encrypt or move to restricted directory |
| JWT token theft with no revocation mechanism | Low | Medium | P2-1 — add `iss`/`aud`, shorten expiry, add refresh token |
| Portal `usage_records` default partition grows unbounded | Low | Medium | **Fixed** — `partition.go` creates rolling monthly partitions at startup |

| S3 lifecycle rules misconfigured on retention prefixes | Low | High | Test lifecycle rules in staging before enabling in prod |
